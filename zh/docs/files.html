文件操作

批量重命名、配置备份快照与只读并排对比。

批量重命名#

在资源管理器里一次改很多个名字：Ctrl+点击 选中多行（Shift+点击 选连续一段），再点行菜单里的「批量重命名 N 项…」。整个文件夹不必先选中——文件夹自己的菜单、以及文件菜单里（作用于它所在的文件夹）都有「批量重命名此文件夹…」，资源管理器当前目录则在空白处的菜单里。

所有名字都先算好、检查过才动磁盘，被拒绝时文件夹保持原样。对话框一边输入一边列出每行的新名字，与同批另一行撞名的会标出来。

两种规则：

  • 规则 —— 把名字拆成 token：{name} 是原名（不含扩展名），{ext} 是扩展名（含点），{n} 是序号。{name}{ext} 什么都不改；photo-{n}{ext} 给整个目录编号；{name}-backup{ext} 给每个名字加后缀。序号从「起始序号」开始，按「补零位数」补零，得到 01、02… 而不是 1、2…。
  • 正则 —— 对完整文件名（含扩展名）匹配，再替换。$1 引用分组，勾上「忽略大小写」等价于加 i，没有匹配到的行保持原名。替换串里同样可以用 {name}、{ext}、{n}，所以分组和序号能一起用：^(.+)\.jpe?g$ → photo-{n}-$1.jpg。

序号按列表里的行计数，不按匹配到的行：正则模式下没匹配上的行也占一个号，这样只改一部分文件时编号不会乱跳。

应用之前可以先排序——原顺序、名称（数字按数值比较，photo-9 在 photo-10 前）、扩展名、修改时间、手动——并在升序、降序之间切换。拖动整行，或用悬停时出现的箭头微调顺序，{n} 跟着屏幕上的顺序走，可以一直调到编号读起来正确为止。与批外已有条目撞名的，后端会拒绝并提示，而不是覆盖；一个文件夹和它里面的条目不能在同一批里一起改。

改名后，正在显示该文件的标签会保留文本、光标和未保存的编辑。该文档的撤销栈会从头开始，因为 Monaco 没有把缓冲区换到另一个路径的接口。预览里太长而被截断的名字，鼠标悬停会显示完整名称。

配置备份#

设置 → 备份 会保存配置的时间戳副本——分组记录丢了就等于标签会话丢了，而这件事没有撤销。默认目录是 %APPDATA%\com.wrolp.editor\wrolp\backups；「更改…」可选别的目录，「改用默认目录」回到默认。目录与 保留数量都存在 settings.json（backupDir、backupRetain）。

  • 一份快照一个文件。 文件名是 wrolp-backup-<YYYYMMDD-HHMMSS-mmm>-<类型>.json，类型为 auto、 manual 或 pre-restore。把几个文件打进一条记录而不是逐个复制，是因为分组和它的文件夹菜单由 分组 id 绑在一起：只恢复其中一个，就可能让菜单指向一个已经不存在的分组。
  • 里面有什么： settings.json、groups.json、file-settings.json、history.json 和 folder-history.json，每个都按它当时的原始文本保存。不含草稿和版本历史——那些是用户数据而不是 配置，复制它们会让快照涨到它所保护的工作那么大。快照本身和它复制的文件一样，是明文 JSON。
  • 自动与手动。 当天的自动快照在应用打开和关闭时各刷新一次，所以它总停在那次切换时的配置。每次刷新 会替换当天更早的自动快照，手动快照不受影响；窗口跨夜一直开着时，由每小时的检查补上。「立即备份」随时 可以另存一份手动快照。「保留快照数」（1–100，默认 20）在写下一份快照时执行，所以调低数字不会立刻 删除旧文件。
  • 恢复。 列表按新的在前，显示时间、类型、所含分组/标签数量和大小。选中一份会再确认一次，然后先 冲刷草稿与分组、为当前状态做一份 pre-restore 安全快照、替换那五个文件并重新加载窗口。草稿不在 快照里，所以它能挺过恢复和重载。恢复不碰 window.json，窗口停在原地。
  • 只认这个目录、这种名字。 后端会拒绝备份目录之外的路径、名字不是 wrolp-backup-*.json 的文件、 比它认识的格式更新的快照，以及损坏的快照——列表直接不显示损坏的那些，而不是提供恢复。

文件对比#

任选两个内容做只读并排 diff，落在一个独立的比对标签页里（标题形如 a.txt ↔ b.txt）。

  • 任一侧都可以是未保存的内容。 标签的 buffer（含未命名标签）与磁盘文件完全同权：未保存 vs 已保存、 未保存 vs 未保存都能比。左侧是你发起比对的那个标签——比的是它当前的内容，不是磁盘；右侧从选择器里 已打开的内容中挑，或用「浏览文件…」选一个没打开的文件。
  • 同一个文件的未保存版本走标签右键的「与已保存版本比对」：左 = 磁盘新读、右 = 编辑器里的 buffer， 侧名带「· 磁盘上 / · 未保存」，与文件被外部改写时的冲突对比取向一致。
  • 快照语义。 比对打开那一刻两侧的文本被冻进标签页，之后继续编辑源内容不会更新它；重跑同一次比对 （同一对来源、同一顺序）即为刷新。比对标签页右键可以交换左右。默认只保留一个比对标签页：新的对比替换 屏幕上的那一个（重跑同一对仍是原地刷新）；在 设置 → 通用 关闭「比对复用同一个标签页」后，改为每次对比 单独开一个标签。
  • 只看变更。 头部的折叠按钮只保留改动行及其前后各几行上下文，隐藏未改动的段落，旁边写明隐藏了 多少行。标签里的快照不受影响，展开即恢复全文；但折叠状态下行号属于折叠后的文本，编辑器内的查找与 复制也只能覆盖可见片段。
  • 只读。 比对视图不能编辑；要改哪个文件就打开哪个文件。
  • 选择器徽标：「未保存」= 该标签有没落盘的编辑；「未命名」= 背后没有文件。图片、设置页和比对标签页 不作为任何一侧出现；同一个来源不会同时出现在左右（磁盘 vs 磁盘、buffer vs buffer 会被拒， buffer vs 磁盘放行——这正是「与已保存版本比对」）。
  • 比对标签页是临时的：不进分组存储，重开应用不复活。关闭源标签不影响已打开的比对（它拿着自己的快照）， 只是再也无法刷新；此时重跑会提示「那个标签页已关闭」。
