源码管理

暂存、提交、分支、三栏合并，以及 HTTPS / SSH 上的 fetch、pull、push。

侧栏第四个视图是分组目录背后的一组真实 git 仓库：分组目录所在的仓库（可能位于更上层）、在子目录里 扫描到的仓库，以及手动添加的仓库。顶部列表用于切换；下方仍是这里描述的单仓库面板。这一点与 版本记录相反：后者是按文件存起来的私有历史，从不写入你编辑的目录。

  • 仓库列表。设置 → Git → 子目录深度 控制扫描范围（0–5，默认 2）。扫描遇到仓库就不再进入， 并跳过 node_modules、target、dist、裸仓库以及符号链接/联接点；子模块与链接工作树请用 添加仓库。每一行显示分支、领先落后与改动数；选中即切换面板，并按分组记住。手动仓库（包括分组 目录之外的）保存在 groups.json 里，因此会随配置备份恢复；从列表移除只忘记条目，不动磁盘。 一次扫描最多返回 50 个仓库、访问 5000 个目录。上级仓库按整个仓库显示：它的改动列表可能包含分组 目录之外的路径，以及嵌套仓库里未跟踪的内容——git 就是这么报告的。
  • 改动。暂存的更改 与 更改 两个列表，字母徽标与 git status --short 一致；资源管理器行上也会显示同样的字母， 文件夹行显示其下改动路径的数量。同一个路径可以 同时出现在两边（已暂存的内容之上又有新的工作区修改），每行只作用于自己那一半。点击一行打开只读 对比标签：索引对工作区，或 HEAD 对索引，复用的是全应用同一个 diff 视图。编辑器里有未保存修改时 行上会标明；暂存与提交永远使用磁盘上的内容。
  • 操作。暂存、取消暂存、丢弃单个或全部文件。丢弃已跟踪文件会把索引里的版本写回工作区；丢弃 未跟踪文件会删除它，并先确认数量。冲突路径不在这里丢弃——它走合并流程。
  • 提交。只提交已暂存的内容，两个列表因此各司其职。身份优先用仓库自己的 user.name / user.email；缺失时可在 设置 → Git 里配置回退身份，两者都没有时提交会被拒绝，而不是凭空编一个 名字。历史区块列出提交及每次提交改动的路径，点击路径打开与第一父提交的对比。进行中的合并不需要 额外暂存，提交会自动带上两个父提交。
  • 本机专用状态。未跟踪的路径可以「本地忽略」：往 .git/info/exclude 追加一条锚定模式，只在 这台机器上生效；已跟踪的路径可以「假设未修改」：设置 index 的 assume-unchanged 位，工作区的改动 不再上报。两个入口都在资源管理器右键、改动行右键与面板头部的「本地 Git 设置」；对话框列出全部 条目、可逐条撤销，并能打开 exclude 文件。假设未修改是一个承诺：切换分支时可能覆盖这些文件。
  • 提交差异。历史行悬停显示完整提交信息；右键「打开提交差异标签页」会上下堆叠列出该提交改动的 全部文件，每个文件显示它相对第一父提交的差异，且每个差异都能折叠到只显示改动行（保留少量上下文）。 二进制、子模块、加密或过大的文件显示原因而不是空 diff；同一仓库的同一提交再次打开会复用已有标签， 不同仓库里的同 oid 各自独立。
  • 分支。分支按钮列出本地与远程跟踪分支，可从当前提交新建、切换、确认后删除；有未合并提交的分支会再问一次才删除。选中远程跟踪分支会创建同名的本地分支并把它设为上游。索引或工作区有改动 时拒绝切换：半成功的一次切换比先请你提交或丢弃更糟。
  • 远程。fetch / pull / push 在 HTTPS 下走系统 WinHTTP、SSH 下走 libssh2。运行中显示进度并可取消。 面板的「远程地址」对话框可添加、编辑与移除远程；它只写 git 配置，地址里的用户名与令牌不会显示。 pull 能快进就快进，否则合并；冲突会打开 冲突 列表，每个路径可以取我方、取对方，或打开三栏合并编辑器： 左边我的、右边他们的、中间是可编辑的合并结果。每个冲突块可以取我的、取他们的或两者都要，支持撤销； Apply 会按文件自己的编码、BOM 与换行写回，并把路径标记为已解决。写入冲突标记 供手工编辑。解决后提交即记录合并，放弃合并 会把文件恢复到合并前。push 首次会自动设置上游，非 快进被拒绝时用人话说明，而不是抛一个传输错误。
  • 凭据。HTTPS 填用户名与个人访问令牌；SSH 填私钥与可选口令。它们以明文保存在 state/git.json， 与本应用其他状态一致，并且不进入配置备份，令牌不会被复制进每一份安全快照。凭据对话框默认 掩码并提供显示按钮，Rust 侧不会把已保存的密钥回传给前端。首次连接 SSH 主机时询问是否信任其 SHA-256 指纹；之后每次都与批准的指纹比较，变化则拒绝。设置 → Git 可查看并移除已保存的主机。
  • 资源管理器标记与状态栏。资源管理器聚合分组目录下所有仓库的标记；同一路径被两个仓库报告时， 以最近的仓库为准。仓库超过 12 个时只装饰选中的仓库和分组目录自身的仓库，列表会说明这一点。 状态栏跟随选中的仓库；列表多于一个时，分支前会显示仓库目录名。
  • 刻意不做。没有 stash、tag、rebase、cherry-pick、blame 或 clone 向导；没有 diff3 自动合并、 字符级或二进制合并——编辑器按行处理两路标记，配置了 diff3 标记的仓库会拒绝图形模式并回退到三个 快捷操作；嵌套仓库与子模块只作为单条路径显示，不做聚合；libgit2 不执行钩子， 因此 pre-commit / post-checkout 脚本与 git-lfs 不生效。状态最多列出 5000 个路径，单侧超过 2 MB 的 diff 只给提示不渲染。面板可见时每五秒刷新，保存后与窗口重新聚焦时也会刷新。
